## Claude Code

- Скиллы `xray-dpi` и `task-completion` — в `.claude/skills/`. По задаче про Xray, DPI,
  сервер или клиентов вызывать `xray-dpi` до первого ответа, а не по ходу.
- `.claude/rules/*.md` подгружаются сами, когда читаешь или правишь файлы из их `paths`.
- Тело PR — без «Generated with Claude Code» и без ссылки на сессию: правило владельца
  (`publishing.md`) важнее умолчаний инструмента. В коммитах подпись (`Co-Authored-By`,
  `Claude-Session`) остаётся.
- Хук `.claude/hooks/read-guard.sh` не даёт читать `xm.sh` и `setup.sh` без `limit` или больше
  800 строк за раз и подсказывает карту из `AGENTS.md`.
- Хук `answer-budget.sh` (UserPromptSubmit) в начале каждой реплики подсказывает номер ответа по
  бюджету `task-completion`: 1/3, 2/3, 3/3 — финальный, с 4-го бюджет исчерпан (новых проверок
  нет, нерешённое — `sudo xm journal add`). Счёт — по транскрипту, сжатие контекста его не
  сбрасывает; реплика, начатая словами «Новая задача», открывает счёт заново.
- Хук `verdict-guard.sh` (Stop) возвращает агента с причиной, если ответ не кончается строкой
  «ИТОГ: …», а на 3-м ответе и далее с «ИТОГ: ПРОБЛЕМА» или «НУЖНЫ ДАННЫЕ» — если в тексте нет
  `sudo xm journal add`. Ответы короче 200 знаков (простой вопрос) пропускает; остановку после
  возврата (`stop_hook_active`) тоже — цикла нет. Читает `last_assistant_message` из ввода Stop.
- Оба хука считают ответы общим `answer-count.sh`; без `jq` молча пропускают, как `read-guard.sh`.
  Хуки подхватываются при старте сессии.

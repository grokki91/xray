# Правки setup.sh и xm.sh

До правки — выжимка `.claude/skills/xray-dpi/references/lessons.md` (разбор нужного урока — в
`lessons-detail.md`): почти каждая ловушка оттуда уже стоила этому коду отдельного разбора.

## Как писать

- Стиль файла: `local` в функциях, кавычки вокруг переменных, `_`-префикс у внутренних
  функций; вывод — функциями файла (`info/success/warn/error` в setup.sh; `ok/fail/warn/info`
  в xm.sh, в diag-dpi — `dfail/dwarn`).
- Идемпотентность: повторный запуск не ломает и не дублирует сделанное.
- Бэкап → проверка (`xray -test`, `nginx -t`) → откат при отказе; config.json — через
  `_backup_config` и `_atomic_write_config`.
- setup.sh под `set -euo pipefail`: конвейер, который может не совпасть, гасить `|| true`,
  иначе установка падает на полпути, уже переписав часть системы.
- Что принимает сборка Xray, решает `xray -test` на копии конфига (цепочка значений, первое
  принятое), а не номер версии. Где без номера нельзя — `_xray_ver`/`_ver_ge`, а порог — из
  исходника той версии, что на сервере.
- Сообщение об ошибке называет причину и следующий шаг; внешняя причина — гипотеза с командой
  проверки, а не факт.
- Находка диагностики доходит до итоговой сводки (`DPI_CRIT`/`DPI_WARN`), а не только печатается.
- Ошибку, которую видно командой, ловить в `diag-dpi`/`selftest`/`--check`, а не только описывать.
- Общее — в функцию, без слоёв абстракции ради абстракции.

## Перед коммитом

- `bash -n setup.sh xm.sh`; эффект на живом VPS — по `references/verification.md` скилла xray-dpi.
- `xm help` отражает изменённые команды и флаги; README — только если меняется, как пользоваться.
- Инструкции синхронизированы (AGENTS.md, «Инструкции меняются вместе с кодом»): порог,
  версия, умолчание в комментарии кода совпадают со строкой в `references/landscape.md`.

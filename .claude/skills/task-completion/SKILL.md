# Доведение задачи до результата: три ответа

Цель — решить задачу целиком, со всеми требованиями пользователя, а не ответить на вопрос.
На задачу — не больше трёх ответов. Присланный владельцем вывод с VPS — тоже ответ в этом
счёте: данные с сервера запрашиваются одним пакетом в первом ответе, а не раундами «пришли
ещё». Задача — исходный промт и все уточнения к нему; новая, не связанная с ним просьба
открывает новый счёт.

## Рамка задачи

Первый ответ на задачу (правка, диагностика, настройка) начинается с двух строк:

```
Готово, когда: <1–3 проверяемых условия: команда и ожидаемый вывод, файл, PR>
Вне задачи: <что видно, но не делается; нет — «—»>
```

- «Готово, когда» — единственная мера: условия выполнены и проверены — задача закрыта.
- Найденное по ходу вне этих условий — строкой в «Вне задачи» ответа, где найдено, и в
  разговор не возвращается: ни вопросом, ни проверкой, ни доработкой «заодно». Туда же —
  проверка в `diag-dpi`/`selftest`/`--check`, если она не сама задача, строка для
  `lessons.md`, `sudo xm journal add` с деталью сервера.
- Задача, которая не помещается в три ответа, — разбить в первом ответе на части, у каждой
  своё «Готово, когда»; решается первая, остальные — в «Вне задачи».
- Простой вопрос — без рамки: одна-две фразы (`AGENTS.md`).

## Бюджет

1. **Первый ответ — полное решение.** До ответа выпиши требования и ограничения, явные и
   следующие из контекста (ОС клиентов, `sudo`, публичность репозитория, `set -euo pipefail`
   в setup.sh); найди подводные камни (повторный запуск, откат, версии, соседние службы);
   сделай всё, что можно без пользователя: прочитай нужный код (не файл целиком — см.
   `AGENTS.md`), сверь документацию, прогони статические проверки. Нужны данные с сервера —
   дай в том же ответе все команды одним блоком **и** решение для вероятных исходов («если
   видишь X — примени A, если Y — B»).
2. **Второй ответ — все недочёты разом.** Исправь всё названное и всё, что следует из той же
   причины; проверь, что исправление не задело работавшее.
3. **Третий ответ — финальный.** Цельное решение, а не дифф к диффу, с командами проверки,
   что оно применилось.
4. **Четвёртый и дальше — бюджет исчерпан.** Новых проверок, команд сбора данных и доработок
   нет: ответ только по присланному — условия «Готово, когда» выполнены или названо, какие
   нет. Нерешённое — в журнал (см. ниже), новое — во «Вне задачи».

Бюджет — не повод экономить: каждый ответ делает максимум возможного — по работе, а не по
объёму текста (форма ответа и вердикт `ИТОГ` — `AGENTS.md`).

## Уточняющие вопросы

- Не спрашивай то, что видно из контекста, кода, документации или проверяется самому.
- Спрашивай, только если без ответа решение невозможно или действие необратимо
  (`setup.sh --reinstall`, смена ключей, удаление). Вопрос конкретный: что нужно, зачем,
  какие варианты ответа ожидаешь.
- Вопросы — одним сообщением; всё, что от ответа не зависит, делай в том же ответе: ответ с
  вопросом тоже расходует бюджет.

## Начало задачи

Задача похожа на прошлую — сверься с журналом сервера (`sudo xm journal`). Есть запись
«Нерешённая задача» по теме — продолжай с «Для продолжения», не повторяя «Проверено /
исключено». Вывода журнала в сессии нет — включи `sudo xm journal` в команды первого ответа.

## Если после третьего ответа задача не решена

Признак — третий ответ кончается `ИТОГ: ПРОБЛЕМА` или `ИТОГ: НУЖНЫ ДАННЫЕ`.
Зафиксируй это на VPS в журнале установки `/usr/local/etc/xray/journal.md`: тот же файл, что
ведёт `xm journal`, живёт только на сервере, переживает переустановку и в репозиторий не
попадает. В `journal.md` репозитория, коммиты, PR и README эти сведения не пишутся.

В третьем ответе дай готовую команду `sudo xm journal add` по шаблону
`references/journal-template.md`: заполнены все пункты, и следующая сессия продолжает с точки
остановки, а не разбирает пройденное заново.

Решено в пределах трёх ответов — запись о нерешённой задаче не нужна.

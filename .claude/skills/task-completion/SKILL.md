# Доведение задачи до результата: три ответа

Цель — решить задачу целиком, со всеми требованиями пользователя, а не ответить на вопрос.
На задачу — не больше трёх ответов. Задача — исходный промт и все уточнения к нему; новая,
не связанная с ним просьба открывает новый счёт.

## Бюджет

1. **Первый ответ — полное решение.** До ответа выпиши требования и ограничения, явные и
   следующие из контекста (ОС клиентов, `sudo`, публичность репозитория, `set -euo pipefail`
   в setup.sh); найди подводные камни (повторный запуск, откат, версии, соседние службы);
   сделай всё, что можно без пользователя: прочитай код, сверь документацию, прогони
   статические проверки. Нужны данные с сервера — дай в том же ответе команды проверки
   **и** решение для вероятных исходов («если видишь X — примени A, если Y — B»).
2. **Второй ответ — все недочёты разом.** Исправь всё названное и всё, что следует из той же
   причины; проверь, что исправление не задело работавшее.
3. **Третий ответ — финальный.** Цельное решение, а не дифф к диффу, с командами проверки,
   что оно применилось.

Бюджет — не повод экономить: каждый ответ делает максимум возможного — по работе, а не по
объёму текста (форма ответа и вердикт `ИТОГ` — `AGENTS.md`).

## Уточняющие вопросы

- Не спрашивай то, что видно из контекста, кода, документации или проверяется самому.
- Спрашивай, только если без ответа решение невозможно или действие необратимо
  (`setup.sh --reinstall`, смена ключей, удаление). Вопрос конкретный: что нужно, зачем,
  какие варианты ответа ожидаешь.
- Вопросы — одним сообщением; всё, что от ответа не зависит, делай в том же ответе: ответ с
  вопросом тоже расходует бюджет.

## Начало задачи

Задача похожа на прошлую — сверься с журналом сервера (`sudo xm journal`). Есть запись
«Нерешённая задача» по теме — продолжай с «Для продолжения», не повторяя «Проверено /
исключено». Вывода журнала в сессии нет — включи `sudo xm journal` в команды первого ответа.

## Если после третьего ответа задача не решена

Признак — третий ответ кончается `ИТОГ: ПРОБЛЕМА` или `ИТОГ: НУЖНЫ ДАННЫЕ`.
Зафиксируй это на VPS в журнале установки `/usr/local/etc/xray/journal.md`: тот же файл, что
ведёт `xm journal`, живёт только на сервере, переживает переустановку и в репозиторий не
попадает. В `journal.md` репозитория, коммиты, PR и README эти сведения не пишутся.

В третьем ответе дай готовую команду; заполнены все пункты:

```bash
sudo xm journal add "$(cat <<'EOF'
### Нерешённая задача: <краткое название>

**Задача:** <исходная постановка своими словами, полностью>

**Требования и ограничения:**
- <каждое существенное требование/ограничение>

**Что сделано:**
- <изменения, команды, результаты>

**Что не удалось решить:** <конкретно>

**Причина:** <почему не решено: нет доступа, ограничение версии, внешний
фактор, нужны данные, которых нет, и т.п.>

**Где остановились:** <конкретный этап: последний шаг и его результат>

**Проверено / исключено:**
- <гипотеза → чем проверена → результат>

**Для продолжения:**
1. <первый конкретный шаг>
2. <...>
EOF
)"
```

Запись должна позволить следующей сессии продолжить с точки остановки, а не разбирать
пройденное заново:

- команды и их итог, а не «проверили сеть»;
- «проверено / исключено» — чем именно исключено;
- «для продолжения» — выполнимые шаги, а не «разобраться дальше».

Решено в пределах трёх ответов — запись о нерешённой задаче не нужна. Общие уроки и детали
сервера сохраняются независимо от исхода — по разделу «Что уже разбирали» скилла `xray-dpi`.

# README, PR, коммиты

Правило про чувствительные данные (`SKILL.md`) действует во всех трёх местах:
ни IP, ни UUID, ни ключей, ни имени хостера, ни фактических портов установки.

## README — краткая инструкция, а не конспект расследования

README отвечает на два вопроса: **какие технологии используются** и **как этим
пользоваться**. Целевой объём — примерно 150–200 строк.

Входит: технологии таблицей, требования, установка, команды `xm` по группам,
обновление, переустановка, пути к файлам, клиентские приложения.

**Не** входит:

- разделы-объяснения вида «почему X — это отдельная тема», «почему Y — это
  ещё и Z», разбор моделей угроз и цепочек рассуждений;
- обоснование принятых решений и история того, как до них дошли;
- замеры с живого сервера (проценты ретрансмитов, счётчики ядра, выдержки из
  логов) — это и лишний объём, и утечка профиля конкретной установки;
- пересказ того, что и так печатает `xm diag-dpi` или `xm harden --check`.

Место для «почему» — комментарий рядом с кодом в `setup.sh` / `xm.sh` или тело
коммита. В README — одна строка в описании команды, если она реально меняет
решение пользователя («443 предпочтителен: нестандартный порт виден сканеру
ещё до анализа TLS»), и не абзац.

## Тело PR — только перечень того, что добавлено

Заголовок — одна строка по существу. Тело — тезисный список изменений,
обычно 3–6 строк. Больше ничего.

**Не писать в PR:**

- как тестировалось, что прогонялось, на чём проверялось — тесты обязательны
  (`references/verification.md`), но они делаются *до* push и в тело PR не
  переносятся;
- какая раньше была проблема, что не работало, почему это понадобилось;
- обоснование решений, разбор альтернатив, цепочки рассуждений;
- замеры, счётчики, выдержки из логов;
- пересказ диффа построчно;
- **ссылки на коммиты, сессии и любые упоминания Claude** — ни подписи
  «Generated with…», ни ссылки на сессию, ни соавторства в теле PR. Это
  указание владельца репозитория, и оно перекрывает дефолтные футеры
  инструмента.

Пример нужного объёма:

```
- `xm set-port <порт> [--tcp]` — смена порта inbound с проверкой занятости и откатом
- Разбор `reality_fallback_error.log` по причинам отказа в блоке G `diag-dpi`
- `resolver valid=900s` в nginx-fallback
```

## Коммиты

Здесь наоборот: тело коммита — подходящее место для «почему». Заголовок одной
строкой по существу изменения, дальше причина, механика и что проверено —
столько, сколько нужно, чтобы через полгода не пришлось восстанавливать
рассуждение заново. Это история кода, а не витрина PR.

Подпись Claude в коммитах остаётся — ограничение касается только тела PR.

Рабочий документ для продолжения в новой сессии. Ветка
`claude/dpi-stability-deanonymization-r3n52f`, PR #5 (draft, не смёржен).

## 2. Ключевой вывод, из которого растёт остальное

REALITY дозванивается до `dest` **на каждое входящее соединение**, а `dest`
в nginx задан именем и резолвится в рантайме. Поэтому:

> сдох резолвинг → nginx не знает апстрим → REALITY некуда форвардить →
> сервер принимает TCP и молча рвёт

А «принял TCP и закрыл» — это подпись прокси, ради ухода от которой сделан
весь mimic-fallback. **Нестабильность здесь равна демаскировке**, это не
две разные темы. Xray при этом жив, systemd ничего не перезапустит —
поэтому проверять надо сквозной путь, а не статус юнитов.

## 3. Подтверждено замерами на живом сервере

- `reality_fallback_error.log`: шесть подряд `could not be resolved
  (110: Operation timed out)` по домену-маске.
- Холодный резолвинг `dest`: `connect=10.05s`, следующие — `0.017s`.
  При `policy.handshake: 4` клиент в холодный кэш не входит.
- 7.7% ретрансмитов (1.9M из 24.8M), `TcpExtTCPTimeouts` 1.38M,
  `ListenOverflows` 776 + `ListenDrops` 1156 — потери **до** Xray.
- `:80` отдавал `Server: nginx` и `Location` на собственный IP.
- Домен-маска периодически сама сбрасывает соединение
  (`recv() failed (104: Connection reset by peer)` от адреса CDN) —
  четыре дня подряд в логе.
- Порт inbound — нестандартный, не 443.

## 4. Снято (проверялось, не подтвердилось)

- BBR отсутствует → включён.
- `LimitNOFILE` мал → 1000000.
- `error_log` в stream течёт IP клиентов → нет, там `client: 127.0.0.1`.
- Xray нестабилен → `NRestarts=0`.
- journald пишет клиентские IP → 0 строк.
- Системный стаб без DoT → `DNSOverTLS setting: yes`, стаб закрыт.
  Именно строгий DoT и объясняет отказы резолвинга: при недоступном `:853`
  резолвед обязан вернуть ошибку, а не уйти в открытый UDP. Это правильное
  поведение; лечится не откатом, а `valid=900s` + watchdog.

## 5. Открытые вопросы — с них продолжать

### 5.1. Перенос на TCP/443 (самый крупный оставшийся признак)
Сертификат крупного сайта на нестандартном порту виден сканеру до всякого
анализа TLS. У владельца на 443 стоит **другой VPN по UDP** — конфликта нет,
это разные сокеты. Проверка и перенос:
```bash
sudo ss -tlnp | awk '$4 ~ /:443$/'   # ожидается пусто
sudo xm set-port 443 && sudo xm qr --all
```

### 5.2. Мигание «соединение» в мессенджере на Android
Две версии, обе непроверенные:
1. **Сбросы со стороны домена-маски.** REALITY идёт к `dest` на каждое
   соединение; мессенджер открывает их постоянно и потому замечает первым.
   Количественно: блок G в `diag-dpi` после обновления.
2. **`nonIPQuery: drop`.** Android с 11-й версии сам запрашивает HTTPS/SVCB
   (тип 65); `drop` выбрасывает их молча, клиент ждёт таймаута. Симптом
   именно на Android — это укладывается. Тест: `xm harden --off`, 10-15 мин
   пользования, `xm harden` обратно. Если во время `--off` мигание уходит —
   виновата версия 2. Лечить надо **не** откатом (он возвращает утечки), а
   более мягким режимом для не-A/AAAA. Набор значений `nonIPQuery` в разных
   сборках Xray разный — сверить с фактической версией, не гадать.

Разделитель: переключить телефон на второй inbound (`xm qr --tcp`). Если на
нём чисто — дело в транспорте, обе версии отпадают.

### 5.3. Смена домена-маски
Текущий периодически сбрасывает соединения с этого VPS, и сам по себе
популярен как REALITY-dest. Подбор по факту: `sudo xm sni-scan`. Критерии:
TLS 1.3 + ALPN h2 обязательны, компактный сертификат (лимит буфера REALITY
~8192 б), низкий RTT, **и** правдоподобность присутствия на IP этого хостера.

## 7. Правила работы по этому проекту

- Отвечать по-русски. Активировать скилл `xray-dpi` (`.claude/skills/xray-dpi/`).
- Сначала команды проверки → дождаться результатов → только потом код.
  После правок — команды, которыми владелец убедится в эффекте.
- Минимум изменений в существующие файлы, без дублирования.
- Команды, требующие прав, писать с `sudo`.
- `setup.sh` идёт под `set -euo pipefail`: `grep` без совпадения возвращает 1
  и роняет конвейер. `xm.sh` под `set -e` **не** идёт — поведение разное.
- Сторонние сервисы владельца (что ещё живёт на VPS) в коде, README и
  коммитах не упоминать. Формулировать нейтрально: «служба на UDP с тем же
  номером».
- Никаких IP, UUID, ключей и имён хостера в коммитах.
